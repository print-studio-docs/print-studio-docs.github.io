文档站维护 ​

本页面向仓库维护者。业务接入从快速开始开始。

启动与构建 ​

在仓库根目录执行：

bash
pnpm docs:dev
pnpm docs:build

pnpm typecheck 在构建库后对 docs/designer、docs/examples、docs/playground 中的 TS / Vue 示例及 .vitepress/components 下的组件与测试进行类型检查。示例从 @printstack/print-studio、@printstack/print-studio/vue、@printstack/print-studio/designer、@printstack/print-studio/core、@printstack/print-studio/printer 公共入口导入，对照当前构建产物验证。

docs:build 先执行上述检查，再构建示例容器和 VitePress 站点。产物为 dist/docs/；部署子路径时设置 DOCS_BASE 后重新构建。pnpm build 包含项目、库与文档站构建。

设计器主题 ​

设计器样式入口 src/styles/design-system.css 依次引入 TDesign、main.css、tdesign-theme.css 和 designer-density.css，供 iframe 和 standalone 模式使用。客户端通过公开入口 @printstack/print-studio/theme.css 复用配色和 TDesign 颜色映射，密度由客户端样式定义。

深色主题使用 data-theme="dark"。theme-mode 仍用于 TDesign 的深浅色模式；浅色模式标记为 data-theme="daylight-blue"，使用浅灰蓝背景、白色表面和蓝色主操作色。背景、文字、边框、语义色及画布辅助标记等颜色在 src/styles/theme-colors.css 定义，预览背景色在 src/styles/preview-colors.css 定义；src/styles/tdesign-theme.css 将设计器色板映射为 TDesign 色阶和交互状态。完整打印预览将所需色板同步到预览 iframe；普通 iframe 预览复用预览背景色板。两者均随所在文档的主题切换更新；纸张与打印内容使用文档自身的颜色。t-alert 使用低饱和底色、语义色边线和常规正文色。深色的输入框占位文字使用 #8290A6；实底主操作和危险操作使用独立底色配白字，按钮在默认、悬停、键盘聚焦和按下时均保持白字；实底警告继续使用亮琥珀底配深色文字。浅色 TDesign 圆角使用 4、6、8、12px。深浅主题复用键盘焦点规则，输入控件的焦点边框和光环随校验状态变化。

深色主题下，面板、菜单及元素设置中的主要选中态使用 #155BD7 配白字；普通表面与悬停状态使用独立的背景色。文本变量标签在画布展示和编辑时均使用浅蓝底、深色文字；无效变量使用深红文字。

打印预览从计算样式读取色板变量，因此 theme-colors.css 使用 @theme static 保留未生成 Tailwind 工具类的变量。

示例容器与浏览器检查 ​

docs:playground 使用构建后的 packages/print-studio/dist 公共入口，将独立 Vue 应用生成到 docs/public/playground/，由文档站复制到输出目录。生成文件已忽略，不提交。docs:dev 和 docs:build 都先准备容器；修改示例源码后需重新执行 pnpm docs:playground。

docs:designer 同样基于 packages/print-studio/dist 公共入口，把 docs/designer/ 构建为全屏独立设计器页面 docs/public/designer/（挂载 @printstack/print-studio/designer 的 attachDesigner，文档持久化到 localStorage）。没有已保存文档时打开内置欢迎模板；已有保存内容时优先恢复。导航栏「设计器」入口指向 /designer/index.html；修改 docs/designer/ 源码后需重新执行 pnpm docs:designer。

文档通过 DemoFrame / PlaygroundEmbed 组件引用容器，使用 withBase 适配站点子路径并附带 embed=1 隐藏容器自带头部；容器自己的资源使用相对路径。仅切换页面不把设计器样式引入文档主题，重置通过重建 iframe 释放旧运行环境。新增运行示例先登记到 playground/example-registry.ts（切换器与入口共用该清单），案例页位于 playground/cases/，复用 playground/snippets/ 中的共享源码；案例 id 必须同步登记到 playground/editor/editor-examples.ts 的编辑模式示例（可运行代码与文档页「在 Playground 中编辑」、案例页「查看代码」均按同 id 解析）；examples/snippets/ 中被 <<< 引用的教学源码保持自包含样式，通过 playground/cases/ 下的案例页包装接入演练场。

通过 PlaygroundEmbed 嵌入的业务打印示例在 playground/editor/business-case-examples.ts 注册，通过 ?raw 载入 examples/snippets/ 中的模板代码和 main.js 入口；initialFile 指定首次打开时显示的文件。入口代码渲染 HTML，并可通过 window.__pgOutput 提供 print() 和 pdf() 操作（pdf() 返回 PDF Blob），预览区只显示已提供的操作。Playground 默认使用「分栏」；文档内嵌时默认收起控制台，为预览留出空间。

执行 pnpm docs:test 验证已构建文档站，首次安装浏览器执行 pnpm exec playwright install chromium。测试覆盖及人工边界见浏览器验收。

教学截图来自实际浏览器，执行 node tests/docs/capture-screenshots.mjs 从端口 4174 的文档预览刷新截图，再重新构建文档。可传入完整的示例地址作为第一个参数。截图需检查启动遮罩已经消失、字体与图片完成加载，不能用占位图代替运行结果。

内容与验证边界 ​

主要入门教程使用 <<< 引用示例源码，避免文案代码和实际文件分离。Markdown 内联片段不会由当前示例类型检查自动覆盖；类型通过与静态站构建通过，也不代表浏览器预览和打印已经验收。

当前站点发布手写指南与 API 参考，不生成完整源码 API 网站。多个指南页共用同一 runner 时，运行案例先在 playground/runner.ts 声明类型，再通过 playground/cases/case-runner.vue 组织运行按钮与输出面板。
