Print Client SDK 与 Print Studio 打印插件实施方案 ​

状态：已实施。 桌面监听使用 /v2，已移除 v1 协议与原 Studio 客户端入口。

1. 目标与现状 ​

网页业务系统应能用一次 print() 调用提交模板和业务数据，并能区分客户端未连接、需要授权、任务已接收和执行失败。已有 Print Studio 集成应只需安装一次插件，保留原有调用方式，通过单次调用参数选择浏览器打印或桌面打印。

当前 protocol 提供连接、认证、RPC、扩展协商以及通用打印契约，但不解释 Print Studio 模板，也不负责业务队列。改造前，桌面客户端接入旧版协议，已有信任审批、打印机选择、任务队列、Print Studio 模板解析与 HTML 渲染，以及 Electron 的 PDF 排版和系统打印。新方案复用这些能力，不重写渲染或执行链路。

2. 包与依赖边界 ​

新建 packages/print-client，包名为 @printstack/print-client。新增代码按客户端、共享契约、宿主注册和 Studio 集成划分；包内维护 AGENTS.md、README 和测试。

公开入口职责
@printstack/print-client网页 SDK：连接、授权接入、打印提交、打印机与任务查询
@printstack/print-client/contracts网页和宿主共用的业务契约及运行时校验；不加载 Vue 或 Node
@printstack/print-client/server将共享契约和宿主处理器注册到 v2；不持有任务、设备或存储
@printstack/print-client/studio设计器插件与无 UI 打印器适配器

protocol 继续提供通用通信。print-studio 只暴露通用打印目标扩展点，不依赖新包或桌面传输。apps/desktop 装配 v2 服务，保有认证审批、设备策略、持久化和实际执行。网页 SDK 根入口不加载设计器、Vue 或 Node 服务端代码。

3. 网页 SDK：从提交到结果 ​

最小调用 ​

ts
import { createPrintClient } from '@printstack/print-client'

const client = createPrintClient()
const job = await client.print({ document: template, input: data })
const result = await client.jobs.wait(job.id, { timeoutMs: 60_000 })

默认连接本机桌面服务，首次提交按需连接；已授权时复用有效凭据，未授权时走桌面审批。SDK 合并同一实例内的并发连接，允许 connect() 提前检查服务、disconnect() 主动断开、dispose() 清理连接与监听。连接状态应足以区分未连接、正在连接、需要授权、可提交和正在重连；认证失败不能表现成普通打印失败。默认地址和首次授权流程须在桌面装配完成后以实际配置为准。

打印内容和设备 ​

ts
const printers = await client.printers.list()

const job = await client.print({
  document: template,
  input: data,
  printerId: selectedPrinterId,
  copies: 2,
  options: { mode: 'silent', paperName: 'A4' },
  idempotencyKey: operationId,
})
  • print() 接收模板与数据，或直接 HTML/PDF，二者互斥。printHTML(html)、printPDF(blob) 复用相同提交逻辑；SDK 负责对直接内容编码。模板默认在桌面端渲染。
  • 不指定 printerId 时，由桌面宿主按授权和设备策略选择打印机；不能确定时复用现有选择流程。网页不猜测系统队列名称，也不能通过 silent 绕过权限策略。getDefault()、select() 和打印机对象快捷方法可在首版闭环后补齐。
  • printerId 在宿主内映射为队列使用的目标设备。份数、纸型、单双面、页码和缩放复用现有宿主参数约束，不建立一套平行语义。

任务状态和安全重试 ​

  • print() 返回已接收的任务，不等待设备执行。jobs.get() 查询快照，jobs.wait() 用有界、可中止的轮询等待终态；jobs.list() 和 jobs.cancel() 复用宿主任务权限与状态规则。事件订阅可后续实现，不作为首版闭环的依赖。
  • 任务成功表示宿主执行流程成功，不证明纸张已实际输出。取消查询或等待不取消桌面任务；已入队任务只能通过明确的任务取消操作处理。
  • SDK 在未提供幂等键时为一次逻辑提交生成键。业务跨调用重试时应传同一个 idempotencyKey，并保持请求内容一致；提交结果未知时，错误应带回该键，便于恢复。真正发起另一份打印应使用新键。
  • 超时或断线不证明任务未入队；重连不自动重发业务请求，不自动切到浏览器打印。对客户端离线、授权失败、设备不可用、模板不支持和内容过大提供可辨识的错误。

4. Print Studio：安装一次，按调用选目标 ​

ts
import { createDesigner } from '@printstack/print-studio'
import { createPrintClient } from '@printstack/print-client'
import { createPrintPlugin } from '@printstack/print-client/studio'

const client = createPrintClient()
const studio = createDesigner()
await studio.plugins.use(createPrintPlugin({ client }))

await studio.print(input) // 原有浏览器行为
await studio.print(input, { target: 'browser' }) // 显式走浏览器
const job = await studio.print(input, {
  target: 'desktop',
  printerId: selectedPrinterId,
  copies: 2,
  options: { mode: 'silent' },
})

插件可选 defaultTarget: 'desktop'；单次调用的 target 优先。未注册的显式目标直接报错，不隐式降级。设计器预览、HTML/PDF 导出和既有预览窗口内的打印按钮不因安装插件改变；本方案的参数切换作用于 print()。

参数含义
target: 'browser' | 'desktop'由谁发起最终打印。浏览器目标打开浏览器打印对话框；桌面目标返回任务句柄。
render: 'browser' | 'desktop'桌面目标的模板渲染位置。默认桌面渲染；浏览器渲染是后续可选项，用于自定义元素只在网页注册等场景。
options.mode: 'preview' | 'silent'桌面端是否经打印预览确认，不用于选择打印目标。

无 UI 场景复用同一个打印目标，不安装设计器插件：

ts
import { createPrinter } from '@printstack/print-studio/printer'
import { createPrintTarget } from '@printstack/print-client/studio'

const printer = createPrinter({ printTargets: [createPrintTarget({ client })] })
await printer.print(template, input, { target: 'desktop' })

扩展方式 ​

在 Print Studio 增加框架无关的 PrintTarget 路由。设计器继续从现有 output.print 命令进入，由受权限约束的扩展点注册目标；createPrinter() 在实例选项中注入相同类型的目标。由路由传入模板与数据快照，浏览器目标继续复用原有浏览器输出；桌面目标将快照交给 SDK，不抢先做一次网页渲染。保留两个目标各自的结果类型和现有错误出口。插件卸载自动注销贡献；外部传入的共享 SDK 由创建者释放。不得替换全局 window.print() 或绕过命令系统直连组件。

5. 桌面宿主接入 ​

text
网页 print() → v2 认证及业务契约 → 桌面适配器 → 队列入库并返回任务
                                              └─ 异步执行：模板反序列化 → HTML
                                                 → Electron PDF 排版 → 系统打印
  1. 以 v2 扩展声明模板和直接内容的结构化请求、打印机及任务操作。契约由 SDK 与桌面共用；宿主在处理器中校验来源、凭据和具体设备/任务权限，不能把 Origin 白名单当成身份认证。
  2. 桌面适配器接入现有审批与信任存储，将稳定认证主体映射为队列 owner，校验打印内容和参数，移交现有队列。同主体同键同内容返回原任务，同键不同内容返回冲突。RPC 处理器不负责渲染，也不等待打印完成。
  3. 复用现有桌面渲染窗口和 Electron 执行器。模板中存在未注册元素时应得到可诊断的失败；直接 PDF 跳过模板解析。客户端与宿主均执行体积限制，考虑 v2 默认 5 MiB 消息预算和 Base64 膨胀；大文件另行设计传输，不先抬高默认限制。
  4. 网页连接桌面服务使用 /v2；旧协议和配对码由 v2 的来源审批及令牌认证取代。云端向内网设备派单不纳入本轮。

6. 实施阶段与验收 ​

阶段交付内容验收
1. SDK 与契约创建新包，实现连接、模板提交、任务查询v2 回环验证协商、认证、参数/结果校验和提交查询
2. 桌面接入注册 v2 业务处理器，复用审批、队列、打印机与执行器网页能完成首次授权，并把模板任务提交到真实桌面链路；拒绝非法来源和越权查询
3. 可靠性直接 HTML/PDF、打印机列表、任务等待与取消、错误及幂等恢复覆盖断线重连、结果未知时同键重试、参数和体积校验，无重复入队
4. Studio 集成通用目标扩展点、设计器插件、无 UI 打印目标未装插件保持原行为；安装、覆盖默认目标、卸载、桌面失败不回退均有测试
5. 交付受影响包的测试和构建，网页接入示例与 API 文档验证浏览器对话框与桌面队列端到端行为，明确哪些结果只表示系统接收

验证范围以新包、print-studio、apps/desktop 及实际受到影响的协议和调用方为限。随实现增量更新新包 README、Studio 输出与插件参考、桌面网页通信 API；未实现的设计不写成现行功能。

7. 已确认决策 ​

  1. 新包命名为 @printstack/print-client。
  2. 使用 target 选择最终打印目标，与渲染位置和桌面预览模式分开。
  3. 在 Print Studio 增加通用打印目标注册机制；桌面侧实现放在独立插件，不写进 Studio 核心。
