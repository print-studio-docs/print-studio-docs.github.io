事件 ​

设计器的全局事件目录（DesignerEventMap）声明了全部语义事件：store 事件绑定层、命令注册表与指针拖拽模块负责发射，任何模块（尤其是宿主与插件）都可以订阅，实现业务侧刷新 UI、联动保存、桥接外部系统。

订阅 API ​

调用回调参数返回值
studio.events.on(name, handler)对应事件的 payload，类型由名称推导() => void 解绑函数
studio.events.on('*', handler)(type, payload)，收到所有事件() => void 解绑函数

事件机制 ​

ts
// 订阅单一事件，回调参数类型随事件名推导；返回解绑函数
const off = studio.events.on('selection:changed', ({ ids, nodes }) => {
  console.log('选区变化：', ids)
})

// 通配监听所有事件（日志 / 调试 / 桥接），回调收到 (type, payload)
const offWildcard = studio.events.on('*', console.log)

// 所属页面或插件卸载时解除订阅
off()
offWildcard()

要点：

  • 命名约定 <域>:<动作>，如 page:added、element:updated。
  • 只有 '*' 表示通配，不支持 'element:*' 前缀匹配。
  • 订阅不回放当前值；先读状态再监听后续变化。只想跟踪核心状态时优先用 studio.state.getSnapshot() / studio.state.subscribe()。
  • 事件 API 只公开 on；单次监听可在回调中调用解绑函数。
  • 回调保持轻量；总线不等待异步回调、不隔离回调异常。
  • 除语义事件外，每个 store action 成功后自动派发泛化事件 action:<子域>.<动作>（见文末），监听方无需等待事件目录更新。

完整事件目录 ​

payload 类型名对应类型定义；{} 表示无业务字段；? 表示可选字段。

文档 ​

事件payload说明
document:changed{}任意文档数据变化（页面 / 元素 / 数据源 / 区块，含拖拽中间态）；读 studio.document.data 取快照
document:loaded{ skippedTypes?: string[] }loadJson() 成功后派发（load() 不派发）
document:new{}新建文档后
document:renamed{ name: string }文档重命名后

页面 ​

事件payload说明
page:added{ pageId: string }添加页面后
page:updated{ pageId: string; patch }更新页面属性（宽高 / 边距 / 背景等）后
page:copied{ newPageId: string; sourcePageId: string }复制页面后
page:removed{ pageId: string }删除页面后
page:activated{ pageId: string }切换活动页后

元素 ​

事件payload说明
element:added{ node: ElementNode; pageId: string }添加元素后
element:removed{ ids: string[]; nodes: ElementNode[] }删除元素后；nodes 为删除前捕获的快照
element:updated{ node: ElementNode | null; patch; transient: boolean }更新元素后；transient = true 表示拖拽 / 输入等未入历史的中间态
element:renamed{ id: string; name: string }重命名后
element:flags-changed{ id: string; locked: boolean; visible: boolean }锁定 / 显隐切换后
element:duplicated{ sourceIds: string[]; sourceNodes: ElementNode[] }副本创建后
element:nudged{ deltaX: number; deltaY: number }方向键微移后（mm）
element:reordered{ nodeId?: string; pageId?: string }叠放顺序调整后
elements:changed{}元素注册表变化（注册 / 注销元素类型），非页面内容变化

元素排版 ​

事件payload说明
element:aligned{ mode: AlignMode }对齐后；AlignMode = 'bottom' | 'hcenter' | 'left' | 'right' | 'top' | 'vcenter'
element:distributed{ mode: AlignMode }按边缘 / 中心等距分布后
element:spacingDistributed{ direction: SpacingDirection }按间距等距分布后；SpacingDirection = 'h' | 'v'

元素分组（图层组） ​

参考线 ​

跟随区块与循环区块 ​

事件payload说明
follow-block:created{ block: FollowBlock }创建跟随区块后

画布与视图 ​

事件payload说明
canvas:background-changed{ color: string; preset: string }画布（页面外区域）背景色变化后；preset 为预设 id，'custom' 表示自定义
zoom:changed{ zoom: number }缩放变化后；1 表示 100%
tool:changed{ tool: string }当前工具切换后（如 select / hand）
settings:changed{ settings: DesignerSettings }编辑器设置变化后；settings 为完整设置对象（网格 / 吸附 / 标尺等）
drag:start{ tag: string }拖拽会话开始；tag 标识交互种类：move / resize / rotate / marquee / create / guide
drag:end{ moved: boolean; tag: string }拖拽会话结束；moved 表示是否实际发生了移动

界面（对话框 / 菜单 / 提示） ​

事件payload说明
dialog:opened{ dialog: DesignerDialogState }打开或从栈中恢复对话框后；dialog.name 见 DesignerDialogName（page / datasource / preview / template-library / new-document 等）
dialog:closed{}当前对话框关闭或挂起后；不代表该会话已结束
context-menu:opened{ x: number; y: number }打开右键菜单；坐标为视口 CSS px
context-menu:closed{}关闭右键菜单后
toast:shown{ kind: 'error' | 'info' | 'success'; text: string }展示提示后

DesignerDialogState 不再包含 returnDialog；父对话框的恢复由会话栈管理。

状态汇总 ​

事件payload说明
state:changed{}活动页 / 历史可用性 / dirty / 选区变化时同步通知；配合 studio.state.getSnapshot() 使用

命令与插件 ​

事件payload说明
command:before{ id: string; args: unknown[] }命令执行前
command:after{ id: string; args: unknown[] }命令成功执行后（顺序：before → 内部通知 → after）
command:error{ id: string; error: unknown }命令执行失败；原错误继续上抛
command:unknown{ id: string }调用了未注册的命令（随后派发 command:error）
commands:changed{}命令注册表变化（注册 / 注销 / 替换）；菜单与快捷键索引据此重建
plugin:registered{ name: string }插件注册后
plugin:disposed{ name: string }插件销毁后
plugin:state-changed{ name: string; status: string }插件状态切换后（启用 / 禁用等）

泛化 action 事件 ​

底层 store action 成功返回后，自动派发 action:<子域>.<动作> 事件，payload 为 StoreActionEvent：

字段类型说明
namestring带领域的 action 名称，如 element.add
argsunknown[]action 入参
resultunknownaction 返回值
ts
studio.events.on('action:guide.add', ({ args }) => {
  console.log('新增参考线：', args)
})
  • 事件先于语义事件之上的通用兜底：一次 API 调用可能同时派发语义事件与 action: 事件。
  • 名称对应底层 action，不能拼 facade 方法名——如 page.create() 底层派发的是 action:page.add。
  • action 失败时派发 action:failed（payload 为 { name; args; error; result: undefined }），不再派发成功事件。
  • 已接入泛化事件的子域共 24 个：canvas / clipboard / config / dataSource / document / element / elementGroup / followBlock / guide / history / layout / navigation / page / panel / plugin / rendering / repeatGroup / scope / selection / template / tutorial / ui / view / zIndex。

触发时机要点 ​

  • 动作事件：底层 action 成功返回后先派发语义事件，再派发泛化 action:<子域>.<动作>；一次 API 调用可能对应多个事件。
  • 状态事件（document:changed、selection:changed 等）由 Vue watch 派生、默认批处理，可能在同步 API 返回后触发；需要等待时用 await nextTick()。
  • state:changed 例外：同步 watch，在活动页 / 历史可用性 / dirty / 选区变化时发出；用 state.getSnapshot() 读快照，无需等 nextTick()。
  • 撤销 / 加载不会逐个重放元素事件；维护完整文档镜像时监听 document:changed 并读取 document.data。
  • payload 可能含内部响应式引用，只读使用；长期保存请经实例查询快照。

与 PrintDesigner 组件事件的区别 ​

<PrintDesigner> 的 Vue 事件为 ready(context)、dirty-change(boolean)、error(error)、dispose（@ready/@dirty-change/@error/@dispose），不属于 DesignerEventMap。实例没有 document:saved / 打印完成事件——保存与输出的后续操作应等待对应 API 的 Promise。
