页面模板与布局扩展 ​

「页面模板」（PageTemplate）是文档内部的主页机制：多个页面共用页眉、页脚、背景等内容，与「模板库」（整份文档的可复用副本）是两个概念。

template API ​

成员功能类型必填说明
template.list全部模板句柄TemplateHandle[]否
template.get(ref)查询模板句柄(ref) => TemplateHandle | undefined否
template.create(options?)创建模板(options?: { id?; name? }) => TemplateHandle否
template.import(source)导入模板对象(source: PageTemplate) => TemplateHandle否
template.update(ref, patch)更新模板(ref, patch: TemplatePatch) => void否TemplatePatch 为部分 name/background/baseTemplateId/facingPages/oddPages/evenPages
template.apply(ref, pages)批量应用模板到页面(ref: EntityReference, pages: EntityReference[]) => void否
template.detach(pageRef)—(pageRef: EntityReference) => void否解除关联并把模板主页面元素复制进页面
template.remove(ref)删除模板(ref: EntityReference) => void否内置空白模板不可删除
templateHandle.page主模板页面句柄TemplatePageHandle否
templateHandle.evenPage偶数页句柄TemplatePageHandle | undefined否facingPages 开启时使用

TemplatePageHandle 的形状为 { readonly data: PageNode | undefined; readonly elements: ElementsFacade; readonly id: string; update(patch: TemplatePagePatch): void }：只有 data / elements / id / update，没有 remove()（模板内容跟随模板生命周期）；TemplatePagePatch 为不含 templateId 的部分页面字段。

示例：公司抬头与页码 ​

ts
const stationery = studio.template.create({ name: '公司抬头与页码' })
stationery.page.update({
  width: 210,
  height: 297,
  margins: { top: 25, right: 10, bottom: 20, left: 10 },
})
stationery.page.elements.add({
  type: 'text',
  x: 10, y: 8, width: 190, height: 10,
  props: { text: '示例公司 · {{ $document.documentName }}', fontSize: 16 },
})
stationery.page.elements.add({
  type: 'text',
  x: 10, y: 283, width: 190, height: 8,
  props: { text: '第 {{ $document.pageNumber }} / {{ $document.pageCount }} 页',
    textAlign: 'center', fontSize: 9 },
})

// 应用到页面；渲染时模板元素显示在页面元素下方
studio.template.apply(stationery, [page, labelPage])

模板继承：update(ref, { baseTemplateId }) 建立继承链（含环形检测）；facingPages: true 时可用 evenPage 定义偶数页变体。

循环区块 repeatGroup ​

把一组元素按数据数组展开：每条数据平铺一份成员元素，超页自动分页。商品标签、货架标签类场景的核心机制。

成员功能类型必填说明
repeatGroup.create(options)创建循环区块(options: RepeatGroupOptions) => EntityHandle<RepeatGroup, RepeatGroupPatch> | undefined否
repeatGroup.list / get(ref)查询EntityHandle<RepeatGroup, RepeatGroupPatch>[] / (ref: EntityReference) => EntityHandle<RepeatGroup, RepeatGroupPatch> | undefined否
repeatGroup.update(ref, patch)更新(ref: EntityReference, patch: RepeatGroupPatch) => void否除 id/pageId 外的部分字段
repeatGroup.remove(ref, deleteElements?)删除区块(ref: EntityReference, deleteElements?: boolean) => void否默认保留成员元素；true 连成员删除
ts
interface RepeatGroupOptions {
  pageId: string // 必填
  elementIds: string[] // 必填，成员元素 ID
  id?: string
  name?: string
  collection?: string // 绑定数组路径，如 'items'，默认 ''
  direction?: 'grid' | 'page' | 'vertical' // 默认 'vertical'；grid 网格平铺，page 每条数据独占一页并保持设计位置
  columns?: number // grid 列数，默认 2
  gapX?: number // mm，默认 2
  gapY?: number // mm，默认 2
  positionMode?: 'fixed' | 'flow' // flow 时后续内容上移
}

成员元素内直接使用行字段（{{ name }}）与 $index。

跟随块 followBlock ​

让元素（如签字区）始终跟随目标内容（如跨页表格）的末尾：

成员功能类型必填说明
followBlock.create(options)创建跟随块(options) => EntityHandle<FollowBlock, FollowBlockPatch> | undefined否必填 pageId/elementIds/target；可选 id/name/gap
followBlock.list / get(ref)查询EntityHandle<FollowBlock, FollowBlockPatch>[] / (ref: EntityReference) => EntityHandle<FollowBlock, FollowBlockPatch> | undefined否
followBlock.update(ref, patch)更新部分 name/gap/target(ref: EntityReference, patch: FollowBlockPatch) => void否
followBlock.remove(ref)删除关系，保留元素(ref: EntityReference) => void否
ts
studio.followBlock.create({
  pageId: page.id,
  elementIds: [signature.id],
  target: { kind: 'element', id: table.id }, // element | followBlock | repeatGroup
  gap: 5, // mm，非负
  name: '签收区域',
})

表尾溢出延续 ​

长表格超出页高时把溢出行延续到专属页面：配置表格 overflow: { templateId } 指向一个 owner: { purpose: 'overflow' } 的页面模板，模板内放置与主表同构的延续表（requiredElements 声明必需元素）。内置发票模板是完整示例（主票面 240×140 mm + 延续清单 210×297 mm）。
